# PinHalo

[English version](README.md)

Закрепляет любое окно поверх остальных по горячей клавише (по умолчанию **Ctrl+Win+T**). Синяя рамка со скруглёнными углами, как у окон Windows 11, показывает, какое окно закреплено.

Небольшая программа на C# в трее, без зависимостей. Собирается компилятором, который уже есть в Windows, — SDK не нужен. В трее называется *Always on Top*.

> **Проверено только на Windows 11 — на Windows 10 не тестировалось.** В коде есть отдельная ветка для Windows 10 (квадратные углы рамки, потому что окна там квадратные), но её проверяли только принудительным включением на Windows 11. Будем рады отзывам от пользователей Windows 10.

## Возможности

- **Горячая клавиша** включает «поверх всех» для активного окна. Повторное нажатие снимает закрепление. По умолчанию Ctrl+Win+T, своё сочетание задаётся в настройках.
- **Второе сочетание открепляет все окна сразу** (по умолчанию Ctrl+Shift+Win+T). Оно показано и в меню значка, рядом с пунктом *Снять все закрепления*; его можно отключить.
- **20 языков интерфейса.** Язык интерфейса Windows подхватывается автоматически; если его нет среди 20, программа работает на английском. Язык можно выбрать и вручную в настройках.
- **Синяя рамка** обнимает закреплённое окно (5 px при 100% DPI). В Windows 11 её углы повторяют скругление самого окна, в Windows 10 углы квадратные, как у окон там.
- **Рамка пропускает клики**, поэтому не мешает тянуть окно за границы.
- **Следует за окном мгновенно.** Положение берётся из событий системы (WinEvent-хуки), а не опросом: рамка не отстаёт при перетаскивании и ресайзе.
- **Правильный слой.** Рамка лежит прямо над своим окном: окна выше закреплённого перекрывают и его, и рамку.
- **Скрывается, когда нужно:** окно свёрнуто, закрыто или развёрнуто на весь экран (видео, игры). У развёрнутого окна рамка рисуется внутри.
- **Лёгкая.** В простое — около 0% CPU и ~10 МБ памяти. Фоновый процесс написан на чистом Win32, без WinForms и GDI+, а окно настроек запускается отдельным короткоживущим процессом. Секундный таймер-страховка работает только пока что-то закреплено.
- **Учитывает DPI каждого монитора.**
- Значок в трее: двойной щелчок открывает настройки; в меню *Настройки…*, *Запускать вместе с Windows*, *Снять все закрепления* и *Выход*. При закреплении и откреплении появляется уведомление.

## Настройки

Открыть настройки: двойной щелчок по значку в трее, пункт *Настройки…* в его меню или повторный запуск `AlwaysOnTop.exe`, когда программа уже работает.

- **Горячие клавиши:** *Закрепить или открепить активное окно* и *Открепить все окна*. Нажмите *Изменить* рядом с нужной, затем сочетание; *Esc* или повторное нажатие кнопки отменяют ввод. Нужен Ctrl, Alt, Shift или Win плюс другая клавиша (F1–F24 можно и без них), и сочетания должны различаться. *Backspace* отключает сочетание «Открепить все», *По умолчанию* возвращает оба.
- Пока окно ждёт сочетание, оно читает клавиши раньше других программ и самой Windows: занятое сочетание при нажатии не сработает, а *Сохранить* сообщит, что оно занято. Ожидание прекращается, как только вы переходите в другое окно. Сочетания, которые Windows держит за собой (Ctrl+Alt+Del, Win+L), поймать нельзя.
- **Язык:** *Автоматически (язык системы)* или один из 20 языков.

Настройки хранятся в `%LOCALAPPDATA%\AlwaysOnTop\settings.ini`. Если при запуске сочетание для закрепления уже занято другой программой, появится сообщение и откроются настройки; если занято только «Открепить все» — появится уведомление.

## Языки

English, 简体中文, हिन्दी, Español, Français, العربية, বাংলা, Português, Русский, اردو, Bahasa Indonesia, Deutsch, 日本語, मराठी, తెలుగు, Türkçe, தமிழ், 繁體中文, Tiếng Việt, 한국어.

Это самые распространённые языки мира (по общему числу говорящих), которые Windows предлагает как язык интерфейса: нигерийский пиджин, которого в Windows нет, заменён корейским, а кантонский покрывает традиционный китайский. Арабский и урду отображаются справа налево.

Переводы лежат в `lang/*.lang` — обычный текст `ключ=значение` в UTF-8 — и вшиваются в exe при сборке. Если в переводе нет какой-то строки, берётся английская. Переводы сделаны машинно и носителями языка не проверялись, так что исправления приветствуются.

Чтобы добавить язык: скопируйте `lang/en.lang` в `lang/<код>.lang`, переведите значения, добавьте код в `Codes` в `Strings.cs` и пересоберите.

## Требования

Windows 10 или 11 с .NET Framework 4.x (он установлен по умолчанию). Разработано и проверено только на Windows 11 (64-бит); на Windows 10 не тестировалось (см. примечание в начале).

## Скачать

Скачайте `AlwaysOnTop.exe` со страницы [Releases](https://github.com/vibegineer/PinHalo/releases/latest) и запустите — программа портативная, устанавливать ничего не нужно, она живёт в трее. Чтобы она запускалась вместе с Windows, отметьте *Запускать вместе с Windows* в меню её значка. Автозапуск указывает на текущее место exe, поэтому сначала положите exe в постоянную папку. Снимите отметку, чтобы убрать автозапуск (уберётся и тот, что настраивает `Install.ps1`).

Exe не подписан цифровой подписью, поэтому при первом запуске Windows SmartScreen может предупредить: нажмите *Подробнее* → *Выполнить в любом случае*. В описании релиза указана его контрольная сумма SHA-256.

## Установка из исходников

```powershell
git clone https://github.com/vibegineer/PinHalo.git
cd PinHalo
powershell -ExecutionPolicy Bypass -File .\Install.ps1
```

`Install.ps1` собирает программу, копирует в `%LOCALAPPDATA%\AlwaysOnTop`, добавляет в автозагрузку (ярлык в папке Startup и ключ `HKCU\...\Run`) и запускает. Повторный запуск обновляет установленную версию и сохраняет ваши настройки. Автозагрузка запускает программу с `--autostart`, поэтому вторая из двух записей тихо выходит, а не открывает настройки.

- Только сборка: `.\Build.ps1` — создаёт `AlwaysOnTop.exe` рядом с исходниками.
- Удаление: `.\Uninstall.ps1` (с `-WhatIf` покажет, что будет сделано, ничего не меняя). Удаляет и `settings.ini`. Если остались закреплённые окна, сначала выберите *Выход* в меню значка в трее, чтобы они открепились.

## Примечания и ограничения

- Окна приложений, запущенных от администратора, нельзя закрепить из обычного процесса: вместо рамки появится уведомление. Это ограничение Windows (UIPI).
- Рабочий стол, панель задач и её всплывающие окна не закрепляются.
- Виртуальные рабочие столы не проверялись. Рамка скрывается, пока Windows «прячет» закреплённое окно, но рамка, созданная на одном столе, может не появиться на другом.
- Несколько мониторов и масштаб не 100% реализованы (DPI каждого монитора), но проверялись только на одном мониторе при 100%.
- Лог: `%TEMP%\AlwaysOnTop.log`.

## Как устроено

Фоновый процесс написан на чистом Win32 и не грузит ничего, кроме `mscorlib`: скрытое окно со своим циклом сообщений, `Shell_NotifyIcon` для значка в трее и `TrackPopupMenu` для его меню. Окно настроек — тот же exe, запущенный с `--settings`: WinForms грузится только в этом процессе, и он завершается вместе с окном. На время настроек фоновый процесс снимает свои хоткеи, а потом перечитывает `settings.ini`.

`BorderOverlay` создаёт на каждое закреплённое окно одно layered-окно, прозрачное для кликов, и сам рисует кольцо в DIB-секцию: только пиксели кольца, сглаженные по расстоянию до скруглённого прямоугольника (premultiplied alpha, `UpdateLayeredWindow`). Хук `SetWinEventHook(EVENT_OBJECT_LOCATIONCHANGE)`, ограниченный потоком закреплённого окна, двигает или перерисовывает рамку; глобальный хук `EVENT_SYSTEM_FOREGROUND` держит правильный z-порядок. Кольцо концентрично окну: внутренний радиус равен радиусу скругления окна (8 px × масштаб DPI в Windows 11), внешний больше на толщину рамки.

Поле горячей клавиши в настройках ставит хук `WH_KEYBOARD_LL` только пока ждёт сочетание (после нажатия *Изменить*) — так сочетание видно раньше, чем его получит владелец `RegisterHotKey` или оболочка. Хук остаётся, пока не отпущены модификаторы: иначе отпускание Win открыло бы меню «Пуск». Свободно ли сочетание, проверяется пробной регистрацией `RegisterHotKey`.
